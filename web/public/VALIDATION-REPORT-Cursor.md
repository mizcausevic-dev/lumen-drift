## Automated file validation

These checks were implemented and, on a passing run, executed against the parsed files. They are not a listening test.

- PASS: Exactly 50 MIDI files, 10 in each of the five groups, IDs 001-050.
- PASS: Each file parses as Standard MIDI Format 0, one track, 480 ticks per quarter.
- PASS: Track name, tempo, and 4/4 time signature are at tick 0. No program change, pitch bend, or controller.
- PASS: Every note-on has one note-off. No unmatched note-off. Note-offs are ordered before note-ons at the same tick.
- PASS: End of track is the only terminal meta, at the declared loop length, after any note-offs on that tick.
- PASS: Pitches are inside 36-96, velocities are 1-127, durations are positive, and no note crosses the loop.
- PASS: The same MIDI pitch is never active twice. Active notes, counted from note-on inclusive to note-off exclusive, never exceed 12.
- PASS: Parsed notes match the note CSV in pitch, tick, duration, and velocity.
- PASS: Beat columns match ticks / 480 within 0.0000000005 beats after half-up rounding to 9 decimal places.
- PASS: Tempo meta matches the index and the half-up rounding of 60,000,000 / BPM. The integer BPM round-trips for every file and for every integer from 70 through 115.
- PASS: Each loop has 2 to 8 harmonic events whose tick intervals partition the loop.
- PASS: Sounding pitch classes outside the named collection match the index. The named collection matches the mode formula. Aeolian is the only name used for natural minor.
- PASS: Chord-symbol intervals are present in the intended voicing. Omitted thirds and fifths are written into the symbol.
- PASS: Roman numeral case matches chord quality: lowercase minor-family, uppercase major-family, measured from the parallel major.

## Duplicate detection

Method, implemented and run:

- Build a map from `(start_tick, duration_ticks)` to the sorted tuple of pitches. Velocity and BPM are ignored. Event order among simultaneous notes does not matter.
- Exact duplicate: the maps are equal.
- Transposition duplicate: the maps have the same keys and the same group sizes, and every pitch differs by one constant.
- Internal repetition: for every divisor from 2 through the bar count, split notes at the segment boundaries and compare the resulting `(pitch, local start, local duration)` multisets. A held note that crosses a boundary is split, so a repeated shorter loop still matches. A pedal that continues under changing harmony does not, because the other pitches differ.
- Shared chord symbols and roman sequences are flagged below for musical review. They are not automatic failures. A shared roman sequence can still be a different piece when the voicing, register, and note rhythm differ. Minor duration or velocity edits are not treated as new pieces, because those edits do not create a new signature under the tests above.

## What was not done

- Audio was not rendered.
- The loops were not auditioned. A browser synth in the listening room can play them later. That is not a claim that listening happened during this build.
- Semantic review of whether a borrowed chord 'feels' nostalgic is the ledger above, not a classifier with a pass score.
- DAW loop audition was not run. Loop length is written in the index because a DAW will not infer it from the file alone.
- The published digest is of the MIDI and CSV payload, not of the zip. Hashing the zip from inside the report would change the zip.
